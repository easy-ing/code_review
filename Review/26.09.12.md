# 방금그곡

## 문제 유형

- 문자열
- 구현
- 시뮬레이션

## 핵심 아이디어

이 문제의 핵심은 **실제로 방송에서 재생된 멜로디를 정확하게 만들어서 기억한 멜로디가 포함되는지 확인하는 것**이다.

특히 `C#`, `D#`처럼 두 글자로 표현되는 음을 일반 문자열처럼 처리하면 문제가 생긴다.

따라서 다음과 같이 `#`이 붙은 음을 한 글자로 치환한다.

```text
C# → c
D# → d
F# → f
G# → g
A# → a
```

이렇게 하면 모든 음을 한 글자로 표현할 수 있어서 문자열 포함 여부를 쉽게 확인할 수 있다.

---

## 풀이 과정

### 1. `#`이 붙은 음을 변환한다

예를 들어:

```text
C#DEFGABC#DEFGAB
```

을 다음과 같이 변환한다.

```text
cDEFGABcDEFGAB
```

따라서 `ABC`가 실제 멜로디에 포함되어 있는지 정확하게 판단할 수 있다.

```python
def convert(melody):
    for before, after in change.items():
        melody = melody.replace(before, after)
    return melody
```

---

### 2. 재생 시간을 계산한다

시작 시간과 종료 시간을 모두 분으로 변환하면 쉽게 계산할 수 있다.

예를 들어:

```text
12:00 → 720분
12:14 → 734분
```

따라서 재생 시간은:

```text
734 - 720 = 14분
```

코드에서는 다음과 같이 계산한다.

```python
start_h, start_m = map(int, start.split(':'))
end_h, end_m = map(int, end.split(':'))

time = (end_h * 60 + end_m) - (start_h * 60 + start_m)
```

---

### 3. 실제 재생된 멜로디를 만든다

악보의 길이보다 재생 시간이 길다면 악보를 처음부터 반복한다.

예를 들어:

```text
재생 시간: 14분
악보: CDEFGAB
악보 길이: 7
```

이면:

```text
CDEFGABCDEFGAB
```

가 실제 재생된 멜로디가 된다.

이를 나눗셈으로 처리한다.

```python
repeat = time // len(melody)
remain = time % len(melody)

played = melody * repeat + melody[:remain]
```

예를 들어 재생 시간이 16분이라면:

```text
16 // 7 = 2
16 % 7 = 2
```

이므로:

```text
CDEFGAB + CDEFGAB + CD
```

가 된다.

---

### 4. 기억한 멜로디가 실제 재생된 멜로디에 포함되는지 확인한다

실제로 방송된 멜로디를 만들었으므로 단순히 `in`을 사용하면 된다.

```python
if m in played:
```

여기서 중요한 점은 **원본 악보가 아니라 실제 재생된 멜로디에서 검색해야 한다는 것**이다.

예를 들어 원본 악보가:

```text
CDEFGAB
```

이고 5분만 재생되었다면 실제 방송된 음악은:

```text
CDEFG
```

뿐이다.

따라서 원본 악보 뒤쪽에 있는 `AB`를 기억한 멜로디로 판단하면 안 된다.

---

### 5. 여러 곡이 일치할 경우 재생 시간이 긴 곡을 선택한다

문제의 조건은 다음과 같다.

1. 기억한 멜로디가 포함된 곡을 찾는다.
2. 여러 곡이 있다면 재생 시간이 긴 곡을 선택한다.
3. 재생 시간까지 같다면 먼저 입력된 곡을 선택한다.

따라서 현재 가장 긴 재생 시간을 저장해 둔다.

```python
if m in played:
    if time > max_time:
        max_time = time
        answer = title
```

`>=`가 아니라 `>`를 사용하는 것이 중요하다.

같은 시간이면 기존 곡을 유지해야 하기 때문이다.

---

## 전체 코드

```python
def solution(m, musicinfos):
    # #이 붙은 음을 한 글자로 변환
    change = {
        'C#': 'c',
        'D#': 'd',
        'F#': 'f',
        'G#': 'g',
        'A#': 'a'
    }

    def convert(melody):
        for before, after in change.items():
            melody = melody.replace(before, after)
        return melody

    m = convert(m)

    answer = '(None)'
    max_time = -1

    for info in musicinfos:
        start, end, title, melody = info.split(',')

        # 재생 시간 계산
        start_h, start_m = map(int, start.split(':'))
        end_h, end_m = map(int, end.split(':'))

        time = (end_h * 60 + end_m) - (start_h * 60 + start_m)

        # 악보 변환
        melody = convert(melody)

        # 실제 재생된 멜로디 만들기
        repeat = time // len(melody)
        remain = time % len(melody)

        played = melody * repeat + melody[:remain]

        # 기억한 멜로디가 실제 재생된 곡에 포함되는지 확인
        if m in played:
            if time > max_time:
                max_time = time
                answer = title

    return answer
```

## 코드 리뷰

### 잘한 점

#### 1. `#` 음을 먼저 정규화한 것

이 문제에서 가장 실수하기 쉬운 부분이다.

```python
C# → c
D# → d
```

처럼 바꾸면 이후 로직에서는 모든 음을 동일하게 한 글자로 취급할 수 있다.

덕분에 별도의 파싱 로직 없이:

```python
m in played
```

만으로 멜로디 비교가 가능하다.

---

#### 2. 원본 악보가 아닌 실제 재생된 악보를 비교한 것

이 문제의 중요한 함정이다.

```python
played = melody * repeat + melody[:remain]
```

을 통해 **방송에서 실제로 들린 부분만** 만든 후 검색하고 있다.

따라서 음악이 중간에 끊긴 경우에도 정확하게 처리된다.

---

#### 3. 동일한 재생 시간에서는 먼저 입력된 곡을 유지한다

```python
if time > max_time:
```

으로 작성했기 때문에 같은 시간이 들어왔을 때 기존 곡을 덮어쓰지 않는다.

문제의 조건인:

> 재생 시간이 같을 경우 먼저 입력된 음악 제목

을 자연스럽게 만족한다.

---

## 주의할 부분

### `>=`를 사용하면 안 된다

다음처럼 작성하면:

```python
if time >= max_time:
```

같은 재생 시간의 곡이 나중에 등장했을 때 기존 곡을 덮어쓴다.

문제에서는 **먼저 입력된 곡**을 반환해야 하므로:

```python
if time > max_time:
```

가 맞다.

---

### 원본 악보에서 바로 `in`을 사용하면 안 된다

잘못된 접근:

```python
if m in melody:
```

이렇게 하면 음악이 반복 재생되거나 중간에 끊기는 상황을 반영할 수 없다.

반드시:

```python
played = melody * repeat + melody[:remain]

if m in played:
```

순서로 처리해야 한다.

---

## 시간 복잡도

곡의 개수를 `N`, 각 멜로디의 길이를 `L`이라고 하면 각 곡에 대해 실제 재생 멜로디를 만들고 문자열 검색을 수행한다.

대략:

```text
O(N × L)
```

수준이다.

`musicinfos`는 최대 100개이고 멜로디 길이도 최대 1439이므로 충분히 처리할 수 있다.

## 총평

이 문제는 겉보기에는 단순한 문자열 문제지만,

- `C#` 같은 음표 처리
- 실제 재생 시간만큼 악보 반복
- 재생 시간보다 짧게 끊기는 경우 처리
- 재생 시간이 같은 경우 입력 순서 유지

까지 모두 고려해야 한다.

특히 **"원본 악보에 기억한 멜로디가 있느냐"가 아니라 "실제로 방송에서 재생된 멜로디에 있느냐"**가 핵심이다.

전체적으로는 **문자열 정규화 → 재생 멜로디 생성 → 포함 여부 확인 → 우선순위 비교**의 순서로 생각하면 깔끔하게 해결할 수 있다.
